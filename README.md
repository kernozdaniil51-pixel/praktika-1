## Проблема

| № | Проблема | Категория CIA | Критичность | Обоснование |
|---|---|---|---|---|
| 1 | Используются простые пароли для учетных записей (123456, qwerty) | C, I, A | Критичный | Позволяет легко получить полный доступ к аккаунтам через брутфорс |
| 2 | Версия веб-сервера (nginx/Apache) устарела и содержит уязвимости | I, A | Высокий | Известные уязвимости старых версий могут привести к RCE или DoS |
| 3 | Включен подробный вывод ошибок (Error Reporting) на самом сайте | C | Средний | Утечка системной информации, путей к файлам и структуры БД для злоумышленников |
| 4 | Отсутствует защита от перебора паролей (Brute-force) на странице входа | C | Высокий | Автоматические скрипты могут бесконечно подбирать пароли без блокировки |
| 5 | В корневом каталоге сайта доступны резервные копии базы данных (.sql.bak) | C, I | Критичный | Скачивание бэкапа дает полный доступ к конфиденциальным данным и структуре БД |

## Формулировка рекомендаций

## Рекомендации

- [ ] Установить политику сложных паролей и принудительно сбросить текущие слабые пароли (системный администратор / пользователи, 1 день)
- [ ] Обновление ПО веб-сервера (nginx/Apache) до последней стабильной версии (системный администратор, 2 дня)
- [ ] Отключить подробный вывод ошибок (Error Reporting) на самом сайте и настроить логирование в файл (разработчик / системный администратор, 1 день)
- [ ] Настройка защиты от перебора паролей (Brute-force) на странице входа (системный администратор, 2 дня)
- [ ] Контролировать выход обновлений плагина обратной связи (системный администратор, регулярно / норма)
- [ ] Удалить бэкап базы данных (.sql.bak) из корневого каталога сайта и изолировать хранилище (системный администратор, 1 час)
- [ ] Сохранять текущие корректные права доступа на конфигурационные файлы (системный администратор, регулярно / норма)

## Итоговая оценка

**Общий уровень безопасности:** критический

**Что сделать в первую очередь:**

1. Удалить бэкап базы данных (.sql.bak) из корневого каталога сайта (прямая угроза утечки всей БД).
2. Сбросить простые пароли для учетных записей и установить политику сложных паролей.
3. Обновить ПО веб-сервера (nginx/Apache) для устранения известных уязвимостей.

**Дополнительная информация**

* Проверка проводилась без прав администратора.
* Использовались только общедоступные инструменты браузера.
* Все рекомендации согласованы с политикой информационной безопасности организации.
